## 4. Approach

**Chosen.** The artifact's technique becomes a dedicated reference file, and the phase files
point at it. This is forced rather than preferred: `phase-3-implement.md` sits at exactly 500
against a 500 cap, so there is literally no room to append, and the plugin's own
"dedicated file per concern" rule makes a new reference the right home anyway.

Three stages, scaling:

```
Phase 3 = foundation wave (solo, every contended write, no business logic)
        → N module tracks, concurrent, each delivering DONE
        → assembly wave (solo, mount + reconcile + real boot)

Scaling (Q7): zero contended writes → foundation wave marked complete with a reason,
              never silently dropped. One track → nothing to assemble, same treatment.
              A two-file change therefore looks exactly like hackify does today.
```

Agent selection, the rule that makes two implementer types coherent:
- foundation wave and assembly wave → `hackify:wave-implementer` (no blind siblings)
- two or more concurrent tracks → `hackify:module-implementer` (own database, blind
  siblings, planned-contract builds, never-destroy-work)
- a single-track round → `hackify:wave-implementer`, because with no siblings the
  blind-sibling rules protect nothing and cost context

**Considered & rejected.** Compressing `phase-3-implement.md` to append the technique;
rejected because it is at the cap and the content is a separate concern. Keeping a thin
`tsunami` alias skill; rejected as a file whose only job is redirection.

## Update log

### Work that shares nothing now happens at the same time

**Problem**
Every piece of a job went out one at a time, in a queue, even when two pieces touched completely different files and neither needed the other. Waiting was the single biggest cost in a long run, and almost none of it was buying anything.

**Root cause**
The workflow only ever asked whether pieces could be ordered, never whether they had to be. Anything that looked like it might clash was put in the queue, and nothing went back to check whether the clash was real.

**Solution**
The plan review now lists everything only one worker can hold at once, a file two jobs both write, a numbered sequence, a single shared test database, and then re-asks each one whether it is genuinely exclusive or only exclusive out of habit. Most are habit. Whatever survives that second question gets settled first, alone, in one pass that writes those shared files and no feature code. Everything left runs as separate tracks at the same time, each track finishing and testing its own piece. One last solo pass mounts everything, reconciles it and boots it for real.

**Verification evidence**
Four tracks ran at once across forty five files in this very sprint with no two of them writing the same file. Every track reported green on its own work while the tree as a whole was still broken, which is precisely the case the final solo pass was added to catch, and it caught it.

**Deployment status**
Shipped in 0.17.0. It is the default, not something you turn on.

----

### The shape shrinks to fit the job

**Problem**
A three stage arrangement sounds like a lot of ceremony to put in front of a two file change.

**Root cause**
Nothing, this was a risk in the design rather than a defect. It is written down because it is the thing most likely to be misread.

**Solution**
The size of a run falls out of what the work actually shares, never out of how big the job looks. Nothing shared means there is no first pass at all. One track means there is nothing to assemble. A stage that does not apply is marked finished with a written reason instead of being dropped in silence.

**Verification evidence**
A single file edit produces one track and no extra stages, which is the same behaviour as before this release.

**Deployment status**
Shipped in 0.17.0.

----

### Two ways to run it instead of three

**Problem**
There were three modes and the differences between two of them were getting thin.

**Root cause**
The autopilot mode existed mainly to skip the sign off step. Once the main workflow got faster, the reason to skip anything got weaker.

**Solution**
Autopilot is gone. Two modes remain, the full workflow and the compressed one for small fixes. Every phrase that used to start autopilot now starts the full workflow, so nothing you already type stops working.

**Verification evidence**
The mode is absent from the source and from all six built packages. A check now fails the build if it ever reappears.

**Deployment status**
Shipped in 0.17.0.

### Workers write down what they finished, while they are finishing it

**Problem**
Progress only existed in the message a worker sent back at the end. If a session died halfway through, everything the worker had already done went unrecorded, even though the work itself was safely on disk.

**Root cause**
Workers were told not to touch the plan file at all, because several of them writing one file at once is the exact clash this release was built to remove.

**Solution**
Split by situation. A worker running on its own writes straight into the plan file's daily log as each piece goes green. Workers running side by side each keep their own small file, and the parent folds those in once the round ends. Nobody ever writes the same file as somebody else.

**Verification evidence**
Read the two sets of instructions against each other to confirm neither can write where the other does.

**Deployment status**
Shipped in 0.17.0.

----

### The house rules now travel with the worker

**Problem**
The engineering rules were being attached to messages from you, and a job handed to a worker is not one of those. Workers had never actually been receiving them.

**Root cause**
The mechanism that attaches the rules only fires on a prompt a person types. Nobody had noticed that a worker does not get one.

**Solution**
The rules a worker is most likely to break, the size limits, the ban on silencing a linter, the ban on claiming something passed without running it, are now written into the worker's own instructions. It is a floor, not a replacement, and the worker is still told to read the full rules.

**Verification evidence**
Confirmed the rules are present in the worker instructions and that the full read is still required alongside them.

**Deployment status**
Shipped in 0.17.0.

### Something finally reads the shell hidden inside the instruction files

**Problem**
Some instruction files carry a small script the worker runs on itself before it reports back. One of them had been broken the whole time. The worker's self check quietly did nothing, and every other check stayed green over it for an entire sprint.

**Root cause**
Those files are documents. No tool opens a document looking for code, so nothing ever tried to run the script inside one.

**Solution**
A new check reads all eleven of those files, pulls out every script, and fails if any of them will not run.

**Verification evidence**
Proved by putting the original defect back exactly as it was, watching the new check go red, then restoring the fix byte for byte and watching it go green.
