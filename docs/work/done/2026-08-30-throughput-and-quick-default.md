## 4. Approach

Four doctrine changes, landed in dependency order.

The budget is one new rule with one home. `contention-dispatch.md` already owns the partition test and declares itself canonical for it, so the per-agent and concurrent-agent budgets go there, inside the existing coarse-to-fine block. That block currently reads "take the one with fewer subsets", which biases toward fat waves and few agents. It becomes budget-aware: keep packing a subset until it reaches the per-agent budget, then split, up to the concurrent-agent budget, and never past a partition condition. Everything downstream already cites this file, so `phase-3-implement.md` needs a pointer rather than a copy, and the one full restatement that does exist, in the spec-reviewer template, is updated in lockstep because it is pinned as a sync-sensitive copy.

Tests move rather than disappear. The implementer stops carrying a RED gate, and a new testing stage runs after the last module wave, inside Phase 3, so Phase 4 still opens onto a tested tree. The stage scales down the same way the foundation and assembly waves already do: nothing to test, marked complete with a reason, never dropped.

Work-doc freshness changes owner and cadence, not mechanism. Tracks still write their own files, because ten agents appending to one markdown file is the exact collision this design removes. What changes is that the parent merges on each return instead of batching to round end.

Routing is pure frontmatter, so flipping the default is a rewrite of three `description:` fields plus the prose and the README table that mirror them. The six carve-outs move from "quick does not fire here" to "these escalate to full", which is the same list read the other way.

The three that did hold: an isolated 300-trial loop of the same pipeline failed 0 times, so it only fires under the full run's load; 3000 trials of `echo "$body" | wc -c` delivered all 40176 bytes every time, so the pipe never truncates; and under bash the validator gets `/usr/bin/grep`, so the gitignore-honouring zsh shim is not involved.

**The instrumented run gave the answer outright.** Temporarily probing the failing branch, then removing the probe byte-identically:

```
PROBE req=**ROLE**   bodylen=40107 rc=0   retry=1
PROBE req=**INPUTS** bodylen=40107 rc=141 retry=1
```

The body is complete and the marker is present on retry. **`rc=141` is 128+13, SIGPIPE.** `echo "$body" | grep -qF "$req"` has `grep -q` exit the instant it matches, leaving the writer pushing 40KB into a closed pipe, and the pipeline reports 141 instead of 0. The same signal can manufacture a green.

**This is the sprint's own lesson landing on the sprint's own gate.** A check that can fail for a reason unrelated to what it tests is the same defect class as a check that can pass for one, and eight sites carried it the whole time. **The transient that looked unexplained had a cause, and it was ours.** Two mid-sprint runs reported `phase-3-implementation.md missing **ROLE**` and did not reproduce on demand. The standing hypothesis, a race against an agent's write, is wrong: it reproduces at about 3 runs in 25 on a tree nothing is writing. The cause is SIGPIPE. `echo "$body" | grep -q` lets `grep -q` exit on its first match while the writer still has 40KB to push, and the pipeline then reports 141 instead of grep's 0. Eight sites in the validator carry that shape. Seven turn it into a false red; `20-templates.sh:90` turns it into a false green, because the branch it feeds asserts absence for build templates. Fixed in RD4A. It belongs in this retrospective rather than a footnote, because the sprint spent three rounds establishing that a check which can pass for the wrong reason is a defect, and its own gate had been doing exactly that the whole time.
