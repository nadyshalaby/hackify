What changed

Validator reliability (SIGPIPE)

Problem

bash scripts/validate-dod.sh failed about one run in nine, reporting that a file was missing a section it plainly contained, naming a different section each time.

Root cause

echo "$body" | grep -q lets the reader exit on its first match while the writer is still pushing 40KB. validate-dod.sh:186 sets 'set -uo pipefail', so the pipeline reports the writer's SIGPIPE (141) instead of grep's 0, and the caller reads it as 'not found'. It is load-dependent because a macOS pipe starts at 16KB and grows to 64KB only when the kernel can spare it, so a body between those sizes is the reachable case.

Solution

Twenty-three sites converted: fixed-string tests use bash's [[ == ]], every regex stays on grep via a here-string, because \s means whitespace to BSD grep -E but a literal s to bash's [[ =~ ]]. Check [84] now refuses any new occurrence across scripts/ and hooks/ and inside the agent prompts' fenced shell blocks.

Verification evidence

Three failures in thirty runs before; zero in the seventy runs against the finished code. All 18 CI commands exit 0. Manufactured reds name [84] and cite the planted file:line; the same text planted as a comment stays green with the skipped-comment counter moving, which proves the line was seen and excluded rather than never reached.

Deployment status

Landed in 0.18.0, uncommitted at time of writing; squashed onto main.
