# hackify, project rules

This is hackify's own tree. The always-on law in `rules/` binds here exactly as it
binds any project the plugin is pointed at, and it is injected on every prompt, so
this file restates none of it. What follows is only what an agent working here
cannot derive by reading the code.

## An agent prompt names every file its agent must open

An agent prompt MUST name, by a path anchored to `{{plugin_root}}`, every rule and
reference file its agent is required to open. The list is exhaustive and closed.

A file may be CITED inside a fenced prompt block only if that same file is on that
prompt's REQUIRED READING list. A citation to a file the agent is never told to open
is a dangling pointer.

The validator in `scripts/validate-dod.d/` enforces the ANCHORED half of that rule:
a citation written as a full `{{plugin_root}}`-anchored path is checked against the
list. A bare citation is screened by no check, because telling a plugin file from one
of the user's own files needs judgment no matcher has, so that half rests on review.

## Never hand-edit a generated file

- **Canonical**, the fenced prompt blocks in `skills/hackify/references/parallel-agents/*.md`.
- **Mirrors**, `agents/*.md`, byte-for-byte copies regenerated by
  `python3 scripts/sync_agent_mirrors.py` and enforced by check [75h].
- **Runtime packages**, everything under `dist/**`, regenerated by
  `scripts/sync-runtimes.sh`.

Edit the canonical file, then run the generator that rebuilds the copies. An edit
made in a mirror or under `dist/` is destroyed by the next sync and reds the gate
until then, and an agent who does not know the two commands hand-edits the copy.

## One gate, and it is the whole gate

`bash scripts/validate-dod.sh` runs every test and every lint this repo has. There
is no per-file runner and no root `package.json`, so a scoped run and a full run are
the same command.

## The file-size cap has two tiers

Ordinary files take the standard cap; sub-agent prompt templates under
`skills/hackify/references/parallel-agents/` and `agents/` take a raised one, because
a dispatched agent has no import and splitting a template is not a cheaper read. Both
bounds are defined once, as `CAP_MAX_LOC` and `CAP_PROMPT_TEMPLATE_MAX_LOC` in
`scripts/validate-dod.d/80-file-size-caps.sh`, and are read from there rather than
copied. Which files qualify, and why: `skills/lawkeeper/references/carve-outs.md`.

## History is not edited

`CHANGELOG.md` and everything under `docs/work/` record what was true when it was
written. A sentence there that a later change made false stays as it is. The repair
goes in the live file; rewriting the record to match today is falsification.
